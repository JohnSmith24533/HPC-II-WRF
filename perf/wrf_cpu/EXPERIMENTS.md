# WRF CPU optimization experiment log

Goal: first establish the fastest reproducible scaling baseline for the unchanged current WRF model, then profile and optimize until the geometric mean speedup across all five original cases is at least 5×. Keep `perf/wrf-cpu`; do not push.

The existing numerical golden remains immutable. Scaling can change MPI decomposition, so cross-rank numerical differences are reported explicitly. A new selected rank configuration must have its own independently repeated, strictly compared full trajectory and restart verification before becoming a performance baseline.

The user selected **wall-clock seconds / timestep** as the primary metric. Calculate complete WRF elapsed wall time (including launch, initialization and all prescribed I/O) divided by the verified number of completed timesteps, and separately retain the mean/median `Timing for main` step timers. Full-run step counts are fixed per case, so this normalization leaves speedup ratios unchanged. S001 started before this clarification; its existing `run.json` and `check.json` retain the wall time and actual step counts needed for the same calculation. No speedup is credited for reducing the grid, duration, physics, output cadence, checkpoint coverage or correctness checks. Final speedups require repeated measurements on the same CPU type and resource limit; use per-case medians and `exp(mean(log(baseline / candidate)))` across exactly five cases.

Timer scope was checked against `frame/module_integrate.F`: `Timing for main` surrounds `med_before_solve_io`, the solve and `med_after_solve_io`. It therefore includes some scheduled I/O and setup; it is neither CPU time nor a pure-compute timer. Do not add its sum to separately reported I/O times, because the intervals overlap. The primary measured process wall time needs no such reconstruction.
